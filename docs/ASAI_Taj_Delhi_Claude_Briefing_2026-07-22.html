5. Twilio WhatsApp (full story)

What was built

  • Twilio account: Direct brand · With code · Notifications
  • WhatsApp Sandbox sender typically whatsapp:+14155238886
  • Secrets in Firebase Secret Manager: TWILIO_ACCOUNT_SID, TWILIO_AUTH_TOKEN, TWILIO_WHATSAPP_FROM
  • Local secrets file: scripts/twilio.env (gitignored)
  • Function: onLiveWriteAlert · region asia-southeast1 · instance asai-taj-delhi-default-rtdb

Why Blaze

Spark cannot make outbound HTTPS from Cloud Functions. Project upgraded to Blaze (pay-as-you-go; free quotas cover light use). Twilio WhatsApp is billed separately by Twilio (sandbox free for testing).

Sandbox constraints (critical)

  • Recipient must WhatsApp join <code> to the sandbox number first
  • Error 63015 = number not joined (or session expired ~3 days)
  • Only joined numbers receive messages; Twilio branding on sandbox
  • Production later: Meta/Twilio WhatsApp Business sender + templates

Proven end-to-end

Alert delivered and Twilio status read for noise threshold test. Example body:

ASAI Taj Delhi alert Noise: 65 dBA (limit 40) Temp 27.9°C · Lux 281.6667 · dB 65 21/7/2026, 7:08:26 pm

Alert debugging tips

  • all hits in cooldown → wait 30 min or delete /ASAITajDelhi/alerts_state
  • Arduino Serial can spike above threshold between publishes; Function only sees live.noise_level at ~15s write — hold loud sound across a publish
  • Check Twilio message SID status if Firebase log shows queued but phone silent

9. Lessons learned

  • ESP32 = 2.4 GHz WiFi only (DMello_5G fails; DMello_4G works)
  • Do not use bare millis() as Firebase timestamp — dashboard marks years-stale
  • Outdoor AQI: aqi.in shows US AQI; don’t mix CPCB math into that comparison
  • Twilio sandbox 63015 = join required
  • Never drop /log for WiFi stability without asking — ASAI is data-first
  • Repo split: Taj lives in asai-taj-delhi, not ac-ir-matrix
